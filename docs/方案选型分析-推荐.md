# dsh-memory 方案选型分析：三种方案对比、推荐与优化

> 状态：**推荐分析**。本文档回答"用哪种方案、优缺点、为什么推荐、能否优化"。
> 基于 `调研与设计-v2-草案.md` 的三块调研输入（AI_Prompt / Claude Code Auto Memory /
> Cline Memory Bank），结合 DeepSeek Harness 的现有能力（agent-instructions 注入管线、
> skill-filesystem、plan-mode 会话内状态）做选型。

## 1. 三种候选方案速览

| 维度 | A: AI_Prompt `.ai/` | B: Claude Code Auto Memory | C: Cline Memory Bank |
|---|---|---|---|
| 本质 | 文件系统约定 + 指令 | 内置记忆子系统 | 文件约定 + 指令模板 |
| 存储位置 | 工作区 `.ai/`（可提交） | 用户级 `~/.claude/projects/<p>/memory/` | 工作区 `memory-bank/`（可提交） |
| 记忆结构 | 分类文件（dev/kb/plan/log/bugs）+ 私域 | **指针式索引 MEMORY.md + 话题文件** | 6 个层级文件 |
| 注入方式 | 会话启动自检指令（Agent 自律） | **每会话自动注入索引前 200 行/25KB** | "每次任务必须读全部"指令（Agent 自律） |
| 写入触发 | Agent 主动 + 会话末覆盖写 dev_last | **turn-end 后台自动抽取 + 显式"remember"** | Agent 主动（"update memory bank"） |
| 检索 | 渐进式 + 可选向量 | **grep（无 RAG）** | 全量读（无检索） |
| 防膨胀 | 无硬边界（规则提醒 200 行拆分） | **200 行/25KB 硬边界 + WARNING** | 无硬边界（靠仪式化流程） |
| 知识/约束分离 | 严格分离（最有价值） | 天然分离（CLAUDE.md vs auto memory） | 分离（rules vs memory bank） |
| 多用户 | 有（.ai/users/{user}/） | 无（单用户） | 无 |
| 团队共享 | 可提交 git | 机器本地（不共享） | 可提交 git |

## 2. 关键差异：三个决定性的设计分叉

### 分叉 1：记忆存工作区还是用户级？

- **工作区**（A、C）：进 git、团队共享、随仓库走。**优点**：换机器/换人可迁移，团队协作时共享项目知识。**缺点**：污染仓库（需 .gitignore 策略）、提交噪音。
- **用户级**（B）：机器本地、个人化。**优点**：不污染仓库、可记个人偏好。**缺点**：换机器丢失、无法团队共享、多机器碎片化。

**关键点**：Claude Code 选用户级是因为它把记忆定位为"Claude 自己的笔记本"（个人学习所得）；
CLAUDE.md 负责团队知识。而我们做的是 harness 的**工作区记忆**——用户明确要"工作区级别的
记忆"（原话："工作区级别的skill在哪"、"像 codex/kilo 那样在工作区有 .codex/.kilo 文件夹
保存工作区专用的 plan/skills"）。**用户的意图已经是工作区级**。

### 分叉 2：注入是自动还是靠 Agent 自律？

- **自动注入**（B）：每会话系统提示词自动带索引。**优点**：不依赖 Agent 自觉，稳定。**缺点**：消耗常驻 token（索引越大越贵）。
- **指令驱动**（A、C）：指令要求 Agent 自己读。**优点**：省 token。**缺点**：**依赖 Agent 自律，实际经常不读**（Cline 的 "MUST read ALL files" 指令再强，模型也会偷懒）。

**关键点**：harness 已有 `agent-instructions` 自动注入管线（AGENTS.md 带预算/增量同步）——**自动注入的基建已存在且成熟**，成本是现成的。选自动注入是"站在已有能力上"，几乎零额外成本。

### 分叉 3：写入是自动抽取还是 Agent 主动？

- **自动抽取**（B）：turn-end 后台判断写入。**优点**：不打断工作流、不会忘。**缺点**：实现复杂（需要监听事件 + 判断"什么值得记"）、可能记垃圾（Claude Code 就被批评记忆膨胀）。
- **Agent 主动**（A、C）：Agent 用工具写。**优点**：实现简单、内容质量可控。**缺点**：Agent 可能忘写。

**关键点**：harness 的 `agent/pre-step`、`turn/end` 事件监听能力已有（我 v1 已实现 pre-step 注入）。
turn-end 自动抽取需要判断逻辑——可以用**轻量规则 + Agent 判断**的折中。

## 3. 推荐：B（Claude Code Auto Memory 范式）+ 三处针对 harness 的优化

### 为什么推荐 B？

**1. 它是唯一被大规模生产验证的方案**。Claude Code 是当前最主流的 AI 编程工具之一，
Auto Memory 是其官方内置功能，经历了真实用户数月的使用、反馈与迭代（issue 实证了 200 行
截断问题、膨胀问题，官方持续在修）。A（AI_Prompt）和 C（Cline Memory Bank）本质都是
"文件约定 + 指令"，依赖 Agent 自律，没有产品级保证。

**2. 它的核心设计直接解决"工作区记忆"的本质矛盾**：
- **记忆会膨胀 → 硬边界**（200 行/25KB + WARNING）
- **上下文窗口有限 → 指针式索引**（常驻只带索引指针，细节外置按需读）
- **检索精度 vs 成本 → grep 而非 RAG**（创始人实证：模型自主搜索 > RAG 基建）
- **记忆会过期 → modified 时间戳 + Auto Dream 整理**

**3. 与 harness 现有能力契合度最高**：harness 已有自动注入管线（agent-instructions），
B 的"索引常驻注入"正是它的形态；harness 有事件监听（pre-step/turn-end），B 的
"turn-end 自动抽取"可直接实现。

**4. 它不排斥 A/C 的优点**：B 的索引+话题文件结构可以承载 A 的知识库分类
（decision/pattern/troubleshooting），也可以承载 C 的状态文件（activeContext/progress）。

### B 的缺点（诚实评估）

1. **上下文膨胀**：常驻注入索引占 token（200 行约 3-4K token），多会话累积明显。
   缓解：maxBytes 可配置、索引精简（指针不存内容）。
2. **记忆质量依赖模型判断**：Claude 自主判断"什么值得记"，可能记垃圾/记错。
   缓解：限定记忆类型 + 用户可编辑 + 时间戳。
3. **grep 检索脆弱**：措辞错位即失忆。
   缓解：渐进式（先索引摘要再按需读）+ 未来可加全文搜索。
4. **多工具碎片化**：记忆锁在 harness 内（与 Codex/Claude 不共享）。
   缓解：纯 Markdown 文件，未来可导出/共享格式（memsearch 理念）。

## 4. 针对 harness 的三处优化（在 B 基础上）

### 优化 1：存储位置 —— 工作区 `.dsh/memory/`（B 是用户级，我们改工作区级）

理由：用户明确要工作区级记忆（与 .codex/.kilo/.dsh/skills 同构）；可提交 git、团队共享；
harness 的 skill-filesystem 已经用 `{projectRoot}/.dsh/skills`，`{projectRoot}/.dsh/memory`
是同一范式，用户心智一致。

代价：不能记"用户个人偏好"（那是 ~/.dsh 级）。**折中**：工作区 `.dsh/memory/` 存项目知识
+ 用户级 `~/.dsh/memory/` 存个人偏好（可选扩展）。

### 优化 2：注入复用 agent-instructions 而非另造管线

B 自己实现了注入；我们**直接复用 harness 已有的 agent-instructions 注入机制**：
- 把 `index.md` + `state.md` 作为补充注入源（或注册为额外的指令候选）
- 继承其字节预算、增量变更同步、替换/移除语义

代价：需要确认 agent-instructions 是否支持"注入自定义文件"（它目前注入 AGENTS.md/CLAUDE.md
候选）。如果不行，退而求其次用我们 v1 已实现的 pre-step 注入（对齐其语义）。

### 优化 3：写入用"规则 + Agent 判断"折中，并加经验确认流

B 是纯模型自主判断（可能记垃圾）。我们加两道闸：
- **写入分类限定**：只允许 decision/pattern/troubleshooting/user 四类（工具 enum 强制）
- **经验暂存确认流**（借鉴 A）：非平凡任务后 Agent 把经验写入 `state.md` 的"暂存"区，
  下次会话提醒用户确认后归档（A 的 dev_last 机制）——兼顾自动化与质量

## 5. 最终推荐形态（一句话）

> **以 Claude Code Auto Memory 为骨架**（指针式索引 + 硬边界 + 自动注入 + turn-end 抽取 +
> grep 检索），**落在工作区 `.dsh/memory/`**（用户意图 + 团队共享），**复用 harness 现有
> agent-instructions 注入管线**，**加 AI_Prompt 的经验暂存确认流**做质量闸门，
> 记忆类型限定四类防膨胀。

## 6. 决策点汇总（需你确认）

| # | 决策点 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 存储位置 | 工作区 `.dsh/memory/` | 用户意图 + 团队共享 + 与 .dsh/skills 同构 |
| 2 | 索引+话题文件 | 是（MEMORY.md 范式 → index.md） | 常驻只带指针，防膨胀 |
| 3 | 硬边界 | 200 行/25KB（可配置）+ 超限 WARNING | Claude Code 实证教训 |
| 4 | 注入 | 复用 agent-instructions（或对齐其语义） | 站在已有成熟能力上 |
| 5 | 写入触发 | turn-end 自动抽取 + 工具主动写 | 自动不忘 + 人工可控 |
| 6 | 检索 | 渐进式（索引→分类→grep 扩展） | grep 够用，向量过重 |
| 7 | 记忆类型 | 四类限定（decision/pattern/troubleshooting/user） | 防垃圾记忆 |
| 8 | 经验确认流 | 暂存→下次会话确认→归档 | AI_Prompt 的质量闸门 |
| 9 | 状态文件 | 单一 `state.md`（含 current + last + 暂存区） | 简化文件数量 |

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 注入膨胀消耗 token | maxBytes 可配置；索引只存指针不存内容 |
| 记忆质量差/记错 | 四类限定 + 经验确认流 + 用户可编辑 + modified 时间戳 |
| Agent 不主动写记忆 | turn-end 自动抽取兜底（不依赖自觉） |
| 记忆漂移（"昨天我们决定…"） | 绝对日期（写入时生成）+ 陈旧条目提示 |
| 与 AGENTS.md 重复 | 文档明确分工：AGENTS.md=约束，memory=知识/状态 |
