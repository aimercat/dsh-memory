# dsh-memory v1.1 P2：跨工作区检索克制化 — 设计规格（定稿版）

> 状态：**定稿**。已吸收第三方评审修订（2026-08-19：通过，需带修订）：
> ① 登记顺序前 N 明确为**过渡排序**——长期升级为「最近活跃/最近命中优先」
> （注册表加时间戳，后续迭代）② 超限/未检索提示放**结果首部** ③ 纪律补
> **负例**（不直接套用别的工作区决策/命令/路径）④ 明确普通 recall **不自动
> 漂移到 across**（需显式触发）⑤ 每工作区结果展示上限（searchMemory 已有
> 每文件 20 行上限，文档明确）⑥ 显式联动 P0.5 `channels.across`（评估
> across 价值：常命中但低复用 → 调小上限）。

## 1. 背景与现状

### 1.1 现状（L3 已投产）

- `memory_recall scope="across"`：遍历注册表**全部**工作区（当前 2 个，未来可能
  30+）→ 每个工作区 grep 全部记忆文件（index/state/archive + 4 知识文件）
- 结果带「工作区\<名\>/」来源标注 + 排除当前工作区 + `crossWorkspace: false` 可关闭登记
- 注入纪律文案已有「跨项目共享」表述，但**未显式声明低置信**

### 1.2 缺陷（评审指出）

1. **无检索上限**：注册表增长后每次 across 读 N × 7 文件——文件 I/O 与返回
   token 随工作区数线性膨胀（meow 作者："烧 token"）
2. **无低置信声明**：模型可能把 A 项目的决策硬套到 B 项目（"人类无法理解的联系"）
3. 无检索侧禁用开关（登记侧已有 crossWorkspace，检索侧无）

## 2. 设计

### 2.1 检索上限（acrossMaxWorkspaces，默认 5）

- `scope=across` 只检索注册表**前 N 个**工作区
- **排序（评审修订）**：登记顺序（追加顺序）是**过渡排序**——确定性优先、不改
  注册表结构；**长期升级为「最近活跃/最近命中优先」**（注册表加时间戳字段，
  后续迭代，本 P2 不实现）
- 超限/未检索提示放**结果首部**（评审修订）：
  `（已检索 5 个工作区，另有 3 个未检索——上限 acrossMaxWorkspaces=5）`
- 上限按**工作区数**计（不是文件数）——简单可预期
- 配置：`acrossMaxWorkspaces: 5`；**0 = 禁用跨工作区检索**（scope=across 返回
  「跨工作区检索已禁用（acrossMaxWorkspaces=0）」）
- **每工作区结果展示上限**（评审确认）：searchMemory 已有每文件 20 行匹配上限
  ——单工作区无法霸榜；文档明确此约束存在

### 2.2 低置信纪律（三处强化 + 负例 + 不自动漂移）

1. **across 返回前缀**（结果首行，评审修订）：
   `（以下为跨工作区检索结果，默认低置信——仅当任务明确与该项目相关时参考，行动前以真实文件为准。不要把别的工作区中的项目决策、命名约定、路径结构、工具命令直接套用到当前工作区，仅视作「可能相关经验」）`
2. **注册表列表**（无 query 时）：同样带低置信说明 + 负例行
3. **MEMORY_DISCIPLINE 注入纪律**（评审修订，一行追加）：
   「跨工作区记忆默认低置信（不套用别区决策/命令/路径）；普通检索不自动跨区，仅显式 scope=across 时使用」
4. **不自动漂移纪律**（评审修订）：模型不应在普通 recall 场景自行漂移到 across；
   仅用户显式要求或当前 scope 已明确是 across 时使用

### 2.3 渐进式精读确认（设计确认，不新实现）

- across 结果保持**匹配行级**（grep 行为）——模型看到命中行后，用
  `memory_recall scope=workspace` 对具体工作区精读——已满足渐进式，无需新增
- 不展开正文、不自动 follow-up

### 2.4 与 P0.5 telemetry 联动（评审修订，显式声明）

- across 命中已由 P0.5 `channels.across` 单独统计（各工作区 stats 独立）
- 联动目的：**未来评估 across 价值**——常命中但低复用 → 调小默认上限；
  成本高但价值低 → 进一步克制或降级为默认关闭
- 本 P2 不新增聚合统计

### 2.5 配置（新增）

```yaml
- id: dsh-memory
  config:
    acrossMaxWorkspaces: 5    # 跨工作区检索上限（0 = 禁用检索）
```

## 4. 测试计划（tests/across-curb.spec.ts）

1. **上限截断**：注册表 8 个工作区 + maxWorkspaces=5 → 只搜前 5；结果**首部**
   标注「已检索 5 个，另有 3 个未检索」
2. **上限 0 禁用**：scope=across 返回禁用提示（不遍历）
3. **低置信前缀 + 负例**：有结果/无结果/注册表列表三处均含低置信与负例说明
4. **工具参数**：`memory_recall scope=across maxWorkspaces=3` 覆盖配置值
5. **每工作区展示上限**：单工作区命中 >20 行时不霸榜（searchMemory 既有行为）
6. **回归**：现有 146 测试全绿（默认 5 上限下行为兼容——当前注册表 2 个工作区不触发截断）

## 5. 决策点（评审已定）

| 决策点 | 结论 |
|---|---|
| 默认上限 5 | ✅ 通过（前提：排序问题已标注为过渡策略） |
| 超限标注位置 | ✅ **首部**（评审修订） |
| 排序 | 登记顺序 = **过渡策略**（文档明确）；长期升级最近活跃/最近命中优先（注册表加时间戳，后续迭代） |
| 低置信文案 | ✅ 当前强度合适 + **补负例**（评审修订） |
| 检索禁用与登记禁用独立 | ✅ 独立（支持） |

## 6. 明确不做

- 不做跨工作区正文自动展开（保持匹配行级，渐进式精读）
- 不做注册表时间戳/活跃排序（**过渡排序已明确**，后续迭代）
- 不做跨工作区 telemetry 聚合（各工作区 stats 独立；channels.across 联动已声明）
- 不做"相似项目自动分组"（超出克制化范畴）
