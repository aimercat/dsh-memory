# dsh-memory 工作区记忆方案调研与设计（v2 草案）

> 状态：**调研中，待与用户确认后定稿**。本文档对比三块输入——AI_Prompt 提示词工程的记忆机制、
> 业界成熟方案（Claude Code / Cursor Memory Bank / Mem0 等）、DeepSeek Harness 现有能力——然后给出
> dsh-memory 插件 v2 的设计建议。

## 1. 背景与问题

Harness 新会话默认是"白纸"：除 AGENTS.md（`dsh-agent-instructions` 注入）与当前会话历史外，
工作区没有跨会话状态。上次做到哪、做过什么决策、踩过什么坑，随会话结束丢失。业界同类工具
（Claude Code / Cursor / Codex）已发展出多套记忆方案，本插件要解决的是同一问题，但基于 harness
的插件化能力实现。

## 2. AI_Prompt 工程的记忆机制（调研对象一）

来源：本地下载的 AI_Prompt 开源工程（跨工具 Agent 治理框架，kilo/claude/copilot/opencode 适配）

### 2.1 工作区布局：`.ai/` 目录

```
.ai/
├── config.yaml          # 全局默认（模型后端、执行模式、自动推进、合并模式）
├── .info.json           # 用户身份 {user: username}（gitignore）
├── dev/                 # 公共开发状态
│   ├── dev_core.md      # 动态规则（[+]/[-] 开关管理，只禁用不删除）
│   ├── current.md       # 当前进度总览（@username 行 + 阶段状态）
│   ├── task_claim.md    # 文件锁定（🔒 防多 Agent 冲突）
│   └── note/dev_note.md # 团队共享笔记
├── plan/                # 计划
│   ├── plan.md          # 大计划（须用户确认才改）
│   ├── plan_index.md / plan_log.md
│   ├── deps.yaml        # 阶段依赖（决定并行/串行）
│   └── {stage}/status.md # 子计划状态机（manual/auto、状态、责任 Agent）
├── kb/                  # 项目知识库（"项目是什么样"）
│   ├── index.md         # 分类索引 + 最近更新 + 图谱说明
│   ├── architecture.md  # 架构决策
│   ├── patterns.md      # 代码模式
│   ├── troubleshooting.md # 排查经验
│   └── setup.md         # 环境搭建
├── log/                 # 团队级日志（按年/月/日归档 + index.md + log.md 30 条摘要）
├── code_review/ bugs/   # 审查结论 / Bug 结论（公共摘要，详情报私域）
├── tmp/                 # 临时（向量索引、图谱缓存，gitignore）
└── users/{user}/        # 私域（gitignore）
    ├── dev_last.md      # ★ 上次会话结束状态（跨会话恢复的核心）
    ├── log/ note/ code_review/ bugs/ tmp/
```

### 2.2 核心机制：跨会话状态恢复（dev_last.md）

`dev_last.md` 是**每次会话末尾覆盖写入**的状态快照，下次会话**先读**以恢复上下文：

```markdown
# 上次操作状态
- 时间: yyyy-mm-dd HH:MM
- 阶段: {当前计划阶段}
- 操作: {一句话描述}
- 文件: {新增/修改的关键文件}
- 当前状态: {进度，如 3/7}

## 待续事项
- [ ] {未完成任务} / {阻塞项}

## 关键决策
- {本会话重要架构/设计决策}

## 经验暂存
- [ ] `architecture`：{待归档经验}  ← 下次会话提醒用户确认后归入 kb/
```

### 2.3 核心机制：知识库自动沉淀闭环

1. **触发**：会话完成非平凡任务（解决新问题/发现模式/做架构决策/踩坑）
2. **暂存**：经验写进 `dev_last.md` 的「经验暂存」区（覆盖写，天然不丢）
3. **确认**：下次会话启动读取，提醒用户确认归档
4. **归档**：确认后写入对应 `kb/{category}.md`，更新 `index.md`，日志记录
5. **查阅**：check-kb skill 渐进式查阅（先索引摘要→按任务特征读相关分类→语义检索回退）

### 2.4 约束与知识分离

| 层 | 文件 | 记录什么 | 优先级 |
|---|---|---|---|
| 永久约束 | `AGENTS.md` | 行为准则、编码规范 | 高（写入保护） |
| 流程约束 | `instructions/core.md` | .ai 工作区操作规范 | 中 |
| 动态规则 | `dev_core.md` | 频繁变动的探索性规则（[+]/[-]） | 低（>10 条提醒清理） |
| 知识库 | `kb/` | 项目事实、经验（**不是约束**） | — |

**核心原则**：约束（怎么做）与知识（项目是什么样）严格分离，调试经验绝不塞进行为约束。

### 2.5 其他机制（对 harness 价值较低部分）

- **状态机**（planned→coding→review→test→done）：与 harness 现有 subagent/workflow/plan-mode 重叠，且其 worktree 并行模型依赖 kilo 特定能力
- **向量检索**（bge-small-zh + 时间衰减融合）：需要 Python + sentence-transformers，重依赖
- **wikilink 图谱 / Obsidian**：个人偏好
- **多工具适配器**：harness 是唯一工具，无意义

## 3. 业界成熟方案（调研对象二，待子代理补全细节）

### 3.1 Claude Code 记忆体系（官方文档 + 源码解析，子代理已补全）

**4 层分层**：

| 层 | 位置 | 谁写 | 内容 | 加载方式 |
|---|---|---|---|---|
| CLAUDE.md（团队） | `./CLAUDE.md` / `.claude/CLAUDE.md`（入库） | 用户/团队 | 规范、工作流、架构 | 每次会话**全文**（目录树上溯） |
| CLAUDE.local.md（个人） | `CLAUDE.local.md`（库外） | 个人 | 个人项目覆盖 | 追加在 CLAUDE.md 后 |
| **Auto Memory**（自动记忆） | `~/.claude/projects/<encoded-path>/memory/` | Claude | 学习与模式（构建命令、调试洞见、偏好） | MEMORY.md 前 **200 行/25KB** 注入系统提示词 |
| rules/*.md（路径作用域） | `.claude/rules/` | 用户 | 特定路径规则 | 每会话读 |

**Auto Memory 存储结构**（`~/.claude/projects/<encoded-path>/memory/`，机器本地、不跨机器、豁免 30 天清理）：

```
memory/
├── MEMORY.md          # ★ 入口索引：每次会话注入前 200 行/25KB（先到者）
├── debugging.md       # 话题文件（Claude 自行命名，YAML frontmatter: name/description/type/modified）
├── api-conventions.md
└── ...                # 任意其他话题文件（按需 Read，不常驻）
```

- 路径编码：`/Users/seb/AI/mem-claude` → `-Users-seb-AI-mem-claude`（斜杠→连字符）；同一 git 仓库所有 worktree 共享
- MEMORY.md 是指针式索引（一行一条 → 指向话题文件），细节外置到话题文件
- 话题文件 frontmatter 含 `modified` 时间戳（v2.1.214+ 自动写），注入前剥离 frontmatter

**四种记忆类型**（只记"代码和 git 推导不出"的信息）：

| 类型 | 内容 | 示例 |
|---|---|---|
| `feedback` | 行为/风格纠错（最高价值） | "Always use named exports" |
| `project` | 进行中工作/决策/事故 | "正在从 Express 迁移到 Fastify" |
| `user` | 关于用户的信息 | "偏好简洁解释；UTC+1" |
| `reference` | 代码位置/环境/命令指路 | "Auth middleware 在 src/middleware/auth.ts" |

**触发条件**（系统提示词注入原文，issue #32 实测）：
- 会话**进行中每轮结束（turn end）**由后台判断写入（非会话末统一写）
- 自动检测：用户纠错、跨会话重复模式、重要决策、错误模式与修复、具体命令参数、未文档化依赖
- 显式触发："Remember that we always use pnpm" / "Save to memory: ..."
- 不触发：并非每个会话都写；不记代码事实（会过期）

**注入与检索**：
- 常驻：MEMORY.md 前 200 行/25KB 每次会话注入系统提示词（超过则启动时 WARNING "Only part of it was loaded"）
- 话题文件：轻量模型（Sonnet）每会话挑选**最多 5 个**相关文件加载；其余按需 Read
- 冷数据（历史 .jsonl）：**grep 搜索**，无向量检索。Boris Cherny（创始人）："我们试过 RAG，但让 AI 自己决定搜什么效果远好于 RAG"
- 写入超限返回错误要求重写索引；接近限制时提示精简

**已知缺点**（重要，v2 要避坑）：
1. **200 行静默截断**：超限条目对模型完全不可见且模型不知道 → 反复犯同一错误
2. **系统提示词膨胀**：auto memory + skills 一起注入使 token 成本显著上升，提前触达用量上限
3. **记忆固化错误/陈旧漂移**：一次错误做法被记下后被自信地回忆；"昨天我们决定…"一周后失真
4. **与外部记忆系统碎片化**（claude-mem 等 MCP 竞争）
5. **与 CLAUDE.md 重复/矛盾**；维护负担（官方建议几周一审 `/memory`）

**5 个结构性限制**（源码泄露分析，Milvus 版）：
1. **200 行索引上限**：MEMORY.md 约 25KB，项目跑几个月后旧条目被挤出，长跨度回忆丢失
2. **grep-only 检索**：字面关键词匹配，措辞错位即失忆（"port conflicts" vs "docker-compose port mapping"）
3. **只存摘要、无推理**：调试步骤和"how"丢失，整理救不回来
4. **复杂性叠加**：CLAUDE.md → Auto Memory → Auto Dream → KAIROS 每层是补丁，底层架构（单工具、本地文件、按会话捕获）不变
5. **记忆锁死在工具内**：切到 OpenCode/Codex 即归零，无导出/共享格式/便携性

**关键设计细节**：
- 系统提示明确要求"memories are just hints — verify against real files before acting"（记忆只是提示，行动前用真实文件核实）——对抗幻觉
- Auto Dream（第 3 层，每 24h+5 会话整理一次）：相对时间戳→绝对日期、合并矛盾条目、删过期条目、压缩回 200 行内
- 索引行 ≤150 字符，只存指针不存内容
- KAIROS（第 4 层）未发布，忽略

**替代方案 memsearch（zilliztech，文章后半部）**：
- **理念**：记忆超越单一 agent——从 agent 抽到独立持久层；**Markdown 是 source of truth**（可读/可编辑/git），向量库只是可重建的影子索引
- 写入：每次会话由轻量模型自动总结追加到当天文件（`.memsearch/memory/2026-03-28.md`），异步向量化
- 检索：语义向量 + BM25 + RRF 融合；三级递进（L1 语义预览 → L2 全上下文 → L3 原始 transcript），在子代理中执行、主会话零 token 开销
- 跨 agent：Claude/OpenClaw/OpenCode/Codex 共享同一格式，任何 agent 写的记忆所有 agent 可搜

**对 dsh-memory 的关键启示**：
- 指针式索引（索引常驻 + 话题文件按需）直接复用
- 硬边界（200 行/25KB）控制常驻开销，且要有"接近限制提醒 + 超限重写"而非静默截断
- 限定记忆类型（feedback/project/user/reference 四分类）避免垃圾记忆
- 检索用 grep/全文而非必须上向量库
- 时间戳 + 陈旧条目提示防漂移
- "记忆只是提示，行动前核实"写进系统提示
- **Markdown 为事实源 + 可重建索引**（memsearch 理念）与我们的 `.dsh/memory` 纯文件方案完全同构，印证了方向正确

### 3.2 Cursor / Cline Memory Bank（官方文档已抓取）

**核心文件结构**（`memory-bank/`，纯 Markdown，层级递进）：

| 文件 | 用途 | 更新频率 |
|---|---|---|
| `projectbrief.md` | 基础文档：核心需求与目标（源头） | 项目启动时建 |
| `productContext.md` | 项目为何存在、解决什么问题、UX 目标 | 低 |
| `activeContext.md` | 当前焦点、最近变更、下一步（**更新最频繁**） | **每会话后** |
| `systemPatterns.md` | 架构、设计模式、组件关系 | 中 |
| `techContext.md` | 技术栈、搭建、约束、依赖 | 低 |
| `progress.md` | 什么能用、什么待建、已知问题 | 里程碑/恢复时 |

**工作机制**（本质是"给 AI 的指令"而非代码）：
- 把一套**自定义指令**（custom instructions）放进 `.clinerules/memory-bank.md`（项目级规则）
- 指令核心：*"我的记忆在会话间完全重置——这不是缺陷，是驱动我维护完美文档的动力。每次任务开始**必须读全部记忆文件**（非可选）。"*
- 关键命令：`initialize memory bank`（建结构）/ `update memory bank`（全面审查更新）/ `follow your custom instructions`（恢复工作）
- 上下文窗口管理：窗口满 → update memory bank → 新会话 → follow instructions，无缝续接

**更新时机**：发现新项目模式时、实现重大变更后、用户请求 update 时、上下文需澄清时

**上下文膨胀控制**：
- 手动触发为主（无自动注入管线）；靠"update → 新会话"的仪式化流程控制
- 可选 **Auto Compact** 处理常规上下文管理，手动 update 留给重要检查点

**与 rules/AGENTS.md 分工**：Cline Rules 存"怎么工作"的指令；Memory Bank 存"项目是什么样"的状态/知识

**对 dsh-memory 的启示**：
- 分层文件结构（project brief → context/patterns/tech → active/progress）比扁平分类更完整
- "会话间完全重置、必须读全部记忆"的指令模板是核心——**让 Agent 把记忆维护当第一职责**
- 手动仪式化流程（update → 新会话 → follow）简单可靠，但依赖 Agent 自律（Claude Code 的自动触发是改进）
- **我们已有 agent-instructions 自动注入管线，比 Cline 的手动仪式更优**——应保留自动注入 + 补充自动写入

**补充（子代理调研增量）**：
- **更新策略**：任务开始读全部 → 工作 → 结束写回；写回与文件一一对应（决策→decisionLog、进度→progress、当前焦点→activeContext）。Roo Code 用 briefing/completion 硬性流程节点；MCP 版用 init/load/update 工具约束（比纯提示词可靠）
- **token 实测**：substrate 把 eager 注入改 lazy-load，token 成本降 ~70%（[PR #62](https://github.com/rookdaemon/substrate/pull/62)）；Nagendhra-web 宣称省 60-80% token
- **社区批评**（重要反模式）：① 维护负担+记忆漂移（agent 忘记更新，过期记忆误导）；② "Markdown 不是记忆"（无结构化检索/冲突消解/自动淘汰）；③ **记忆系统可能比无记忆更差**（过时记忆让 agent 更固执）；④ append-only 无淘汰必漂移
- **工具化控制**：fockus 提供 `/mb recall`（默认压缩索引、`--expand` 展开）/ `/mb compact`（状态衰减归档）/ `/mb conflicts`（矛盾检测）；diaz3618 有 status-prefix + compact/purge
- **跨 agent 可移植**：fockus 的 `.memory-bank/` 被 8 种客户端读取（靠 hooks 自动加载），`agreements.md` 镜像写回 CLAUDE.md/AGENTS.md

### 3.3 Mem0 / 知识图谱流派（初步评估）

- **Mem0**：LLM 自动从对话中抽取记忆 → 向量库 + 图数据库存储 → 查询时检索注入。提供
  add/search API、记忆去重与更新时间衰减。适合多会话长期记忆产品。
- **评估**：对单机插件场景**过重**——需要外部服务/API key、向量库运维，且 Claude Code 的
  实践已证明"模型自主 grep > RAG"（创始人原话）。**不建议 v2 采用**；如未来需要跨会话
  语义检索，优先评估 harness 现有 session-query（全文匹配）而非引入向量栈。
- 知识图谱（memgraph/supermemory 等 2026 记忆战争）：同为重方案，v2 不做。

### 3.4 对比总结（更新）

| 维度 | AI_Prompt | Claude Code Auto Memory | Memory Bank | dsh-memory v1 |
|---|---|---|---|---|
| 存储 | 工作区 `.ai/`（可提交） | 用户目录 `~/.claude`（机器级） | 工作区 docs/（可提交） | 工作区 `.dsh/memory/` |
| 写入触发 | Agent 主动 + 会话末覆盖 | 自动（触发条件待确认） | Agent 主动 | Agent 主动（工具） |
| 注入方式 | 会话启动自检指令 | 自动注入（待确认全量/摘要） | 任务开始读 | pre-step 注入摘要 |
| 检索 | 渐进式 + 向量可选 | 待确认 | 按需读文件 | 渐进式（索引→分类） |
| 知识/约束分离 | 严格分离 | CLAUDE.md 与 auto memory 分离 | 分开文件 | v1 未明确 |

## 4. Harness 现有能力盘点（调研对象三）

### 4.1 已有：工作区指令注入（dsh-agent-instructions）

- `~/.dsh/AGENTS.md` 全局 + 工作区根/嵌套 `AGENTS.md`/`CLAUDE.md` 自动加载
- `projectRootMarkers` 可配置（默认 `.git`）、`maxBytes` 字节预算、`maxSourceBytes` 单文件上限
- **增量变更同步**：文件变化时模型可见摘要自动更新（digest + changes）
- 嵌套目录发现、去重、截断、预算控制完整

**结论**：注入管线已有且成熟，v2 不应另造，应让记忆注入**复用/对齐**这套机制（甚至可以考虑把记忆文件注册为指令候选的补充源）。

### 4.2 已有：项目级 skills（skill-filesystem）

- `{projectRoot}/.dsh/skills/`（项目级）+ `~/.dsh/skills`（用户级）+ 自定义根
- YAML frontmatter（name/description）+ 正文，watch 热更新

**结论**：记忆工具可以用 skill 形式（如 `memory-recall` skill）而非硬编码工具，但工具形式更可控（参数校验、输出结构化）。

### 4.3 已有：plan-mode / subagent / workflow

- plan-mode 是会话内 logged state，**不落盘工作区**——这是与 AI_Prompt 的最大差距
- subagent/workflow 已有，无需重造

### 4.4 缺失（v2 要补的）

1. **跨会话状态恢复**：无 dev_last 等价物
2. **知识库自动沉淀**：无 kb 等价物（`.agents/notes` 仅 harness 自用）
3. **记忆的"写"路径**：Agent 无工具主动持久化经验

## 5. v2 设计建议（草案，待确认）

### 5.1 目录布局（工作区 `.dsh/memory/`，可提交）

```
{projectRoot}/.dsh/memory/
├── state.md          # ★ 当前进度 + 上次状态（合并 current/last，见 5.4）
├── decisions.md      # 架构决策
├── patterns.md       # 代码模式
├── troubleshooting.md # 排查经验
└── index.md          # 自动维护的索引
```

### 5.2 注入：复用 agent-instructions 纪律 + Claude Code 的指针式索引

- pre-step 注入 `index.md` 前 N 行（指针式索引，一行一条 → 指向话题文件）+ `state.md` 摘要，字节预算内
- **硬边界**（Claude Code 教训）：索引文件设行数/字节双上限（如 200 行/25KB 可配置），超限时注入 WARNING 而非静默截断
- 不重复造注入管线；对齐 agent-instructions 的「替换/移除」语义

### 5.3 工具

- `memory_recall`：渐进式（索引 → 分类文件 → 原始路径，防穿越）；可选扩展为 grep 搜索（Claude Code 的做法：模型自主搜索 > RAG）
- `memory_update`：追加条目 + 重建索引；条目限定四类型（decision/pattern/troubleshooting/user），避免垃圾记忆
- `memory_state`：更新 state.md（当前进度/待续），替代 dev_last 的覆盖写
- （可选）`memory_remember`：显式"记住…"通道（对应用户说 "Save to memory"）

### 5.4 与 AI_Prompt / Claude Code 的关键差异决策（需你拍板）

| 决策点 | 选项 A（贴近 AI_Prompt） | 选项 B（贴近 Claude Code） |
|---|---|---|
| 存储位置 | 工作区 `.dsh/memory/`（可提交、团队共享） | 用户级 `~/.dsh/memory/<project>/`（个人、机器本地） |
| 状态文件 | `current.md` + `last.md` 分离，会话末覆盖写 last | 单一 `state.md`，Agent 随时更新 |
| 写入触发 | Agent 主动（工具）+ 会话末 | Agent 主动 + **turn-end 自动抽取**（Claude Code 模式） |
| 用户私域 | `.dsh/memory/users/{user}/`（多用户隔离） | 无私域（单人场景） |
| 写入确认 | 经验暂存→下次会话提醒确认 | 直接写（信任 Agent 判断） |
| 语义检索 | 可选（bge 向量，重） | 不做向量，用 grep/全文（Claude Code 结论） |
| 记忆类型 | 不限 | 限定四类（decision/pattern/troubleshooting/user） |
