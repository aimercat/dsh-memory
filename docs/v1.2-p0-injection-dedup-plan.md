## 1. 背景与现状

### 1.1 现状

- `agent/pre-step` 每 turn 注入记忆摘要（工作区索引 + state + 用户级索引 + 纪律）
- 已有 **turn 级 dedup**（`lastInjectedTurns`：同回合多 step 只注入一次）
- **但 turn 间无去重**：内容不变也每 turn 重发

### 1.2 缺陷

- 20 回合会话 = 20 次相同摘要注入（假设记忆未变）——token 浪费 50-90%
- KV 缓存：内容稳定时重复文本破坏前缀复用（每次都是完整新文本块）

## 2. 设计

### 2.1 核心机制：注入文本内容哈希 + 强制刷新

```
pre-step 注入流程（改造后）：
1. 计算注入文本 text（稳定基线 + 易变尾部，与现状一致）
2. hash = fnv1a64(text) + text.length（双校验）
3. 缓存键 = sessionId|agentId（组合，防 agentId 非唯一）
4. 缓存命中（hash+len 相同）？
   ├─ 是且 skipCount < dedupeRefreshTurns → 跳过注入，skipCount+1，skippedInjectionCount+1
   ├─ 是但 skipCount ≥ dedupeRefreshTurns → 强制重注入，skipCount 清零，forcedRefreshCount+1
   └─ 否（首次/内容变化）→ 注入 + 更新缓存（skipCount=0）
```

- **强制刷新**（评审必改）：连续跳过 `dedupeRefreshTurns` 次后强制重注入——
  防长会话上下文截断/压缩/重建后「缓存认为安全、实际上下文已丢失」
- **哈希对象 = 最终注入文本**——完全一致才跳过，任何内容变化都触发重新注入
- 模块级 `Map<sessionId|agentId, {hash, len, skipCount}>`——**会话内去重，
  跨会话不共享**（新会话首次必注入；桌面重启后缓存丢失 → 重新注入一次，合理）

### 2.2 稳定基线 / 易变尾部分层（评审建议）

- **稳定基线**：工作区索引 + state + 用户级索引 + 纪律文案
- **易变尾部**：压力提醒（水位/冷候选数）——保持**短、稳定、后置**：
  - 压力提醒已有独立冷却（不常变）✓
  - 冷候选数只在压力状态时出现（最小化）✓
  - 尾部变化会触发重注入（正确），分层文档化避免尾部膨胀侵蚀去重收益

### 2.3 与现有 turn 级 dedup 的关系（叠加不冲突）

| 机制 | 作用域 | 防什么 |
|---|---|---|
| `lastInjectedTurns`（现有） | turn 内 | 同回合多 step 重复注入 |
| `lastInjectedHash`（新增） | turn 间 | 内容不变跨回合重复注入 |

- 顺序：turn 级检查在前（已注入过本 turn 直接返回）→ 内容哈希检查在后
- turn-end 提醒（确认流/压力提醒冷却）**不参与哈希去重**——它们是动作提示，
  有自己的冷却机制，且内容多变（第 M 次提醒）

### 2.4 安全性论证

- **记忆更新必可见**：`memory_update` / `memory_state` 写入 → 索引/state 变化 →
  注入文本变化 → 哈希不同 → 下一 turn 重新注入 ✓（模型立刻看到新记忆）
- **跳过 ≠ 丢失**：跳过时模型上下文已有完全相同文本；强制刷新兜底长会话
- **哈希可靠性**：fnv1a64（BigInt）+ 长度双校验——冲突漏注入概率可忽略

### 2.5 轻量观测（评审建议）

- 模块级 `skippedInjectionCount` / `forcedRefreshCount` 计数器
- 日志可见（debug 级），不进正式 stats、不 UI 展示——用于验证去重收益与
  强制刷新频率是否合理

## 3. 实现要点

| 文件 | 改动 |

## 4. 测试计划（tests/injection-dedup.spec.ts）

1. **内容不变跨 turn 去重**：连续两 turn 注入一次（第二 turn 跳过，不进入消息批次）
2. **强制刷新**：`dedupeRefreshTurns=3` 时连续 3 次跳过 → 第 4 turn 强制重注入
3. **记忆更新后重新注入**：`memory_update` 写入 → 下一 turn 哈希变化 → 重新注入
4. **首次会话必注入**：无缓存时注入
5. **配置关闭**：`dedupeInjection: false` 恢复每 turn 注入（旧行为）
6. **与 turn 级 dedup 兼容**：同回合多 step 仍只注入一次
7. **压力提醒文本变化触发重注入**：水位状态变化 → 文本变 → 重注入
8. **回归**：现有 154 测试全绿

## 5. 决策点（评审已定）

| 决策点 | 结论 |
|---|---|
| 哈希粒度 | 最终注入文本（完全一致才跳过）；稳定基线/易变尾部分层文档化（评审建议） |
| 哈希算法 | **fnv1a64（BigInt hex）+ 长度双校验**（评审必改统一） |
| 缓存键 | **sessionId\|agentId 组合**（评审必改） |
| 跨会话缓存 | 不共享（新会话注入一次是合理成本） |
| turn-end 提醒去重 | 不做（独立冷却已覆盖） |
| 观测 | 轻量 skip/refresh 计数 + debug 日志（评审建议） |

## 6. 明确不做

- 不做 turn-end 提醒哈希去重（独立冷却机制已覆盖）
- 不做跨会话缓存共享（新会话注入一次是必要成本）
- 不做"部分注入"（只注入变化的区块）——文本级去重已够，区块级复杂度高
- 不做 FTS5/影子索引（提速项，另行评估）
