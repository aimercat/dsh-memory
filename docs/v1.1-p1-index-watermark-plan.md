# dsh-memory v1.1 P1：索引双阈值（高/低水位）— 设计规格（定稿版）

> 状态：**定稿**。已吸收第三方评审修订（2026-08-19：通过，需带修订）：
> ① lowWater 语义明确为**推荐健康目标线（结果评价线 + 建议依据）**——compact
> 不保证收敛（不自动删知识，与 P0.5「冷候选不自动清理」一致），但报告明确差距
> 与下一步路径 ② ratio 校验 `0 < low < high < 1`（非法回退默认）③ 压力提醒
> 独立冷却 + **状态变化重置提醒资格** ④ 压力提醒只带冷候选数量不带明细
> ⑤ compact 未达低水位给**明确下一步建议**（非笼统文案）⑥ report 单状态展示。

## 1. 背景与目标

### 1.1 现状缺陷

- 只有**单阈值**（`maxIndexLines=200` / `maxIndexBytes=25KB` 硬上限 + 超限 WARNING）
- 无"接近上限"预警：索引贴着上限跑，一旦超限才 WARNING——**每次超一点点就
  提醒/微修**（评审引用的 Claude Code #83114 模式：`MEMORY.md went 55 bytes
  over cap — trimming my own line`）
- `memory_compact apply` 无明确"整理目标"：合并/归档后是否健康无从判断
- 无水位可视化：report 只有「行/字节 vs 上限」原始数字

### 1.2 目标

1. **双阈值**：高水位（触发整理信号）≠ 低水位（整理目标），消除微修税
2. 高水位行为：**注入 WARNING + 建议整理**（提醒，不自动执行——整理脱离主任务路径）
3. 低水位语义：`memory_compact apply` 的目标水位；整理后报告水位
4. 水位可视化：report 展示当前水位百分比 + 高/低水位线
5. 与 P0.5 telemetry 联动：冷候选（窗口内 0 命中）作为整理候选参考

## 2. 设计

### 2.1 水位定义

```
0 ─────────────── lowWater ───────────── highWater ──── hardCap ──→
   健康区             │                     │              │
                     │                     └─ 压力区：注入 WARNING + 建议整理
                     └─ 推荐健康目标线（结果评价线 + 建议依据）
```

- **hardCap**：现有 `maxIndexLines` / `maxIndexBytes`（硬上限，超限截断 + WARNING 不变）
- **highWater** = hardCap × `indexHighWaterRatio`（默认 0.8）
- **lowWater** = hardCap × `indexLowWaterRatio`（默认 0.6）
- **ratio 校验**（评审修订）：`0 < indexLowWaterRatio < indexHighWaterRatio < 1`；
  非法配置（反向/等值/越界）**回退默认值**并在日志警告
- 水位按**行数/字节双维度分别计算**，任一维度越线即触发对应状态（评审确认）

### 2.2 行为

| 状态 | 判定（任一维度） | 行为 |
|---|---|---|
| 健康 | 行数/字节 < highWater | 注入不含压力提示（现状不变） |
| 压力 | highWater ≤ 行数/字节 < hardCap | 注入 WARNING：「索引接近上限（水位 xx%），建议运行 memory_compact；当前统计窗口内有 X 条冷候选可供优先整理」 |
| 超限 | 行数/字节 ≥ hardCap | 现有 WARNING（部分条目未加载）保留，合并压力提示 |

- **不自动整理**：任何水位都不在主任务回合内自动跑 compact（评审约束）；
  高水位只提醒，整理由 agent 显式调用
- **压力提醒去重**（评审修订）：独立 `pressureCooldownTurns`（默认 5）冷却 +
  **状态变化重置资格**——以下任一情况重新允许提醒：
  1. 冷却结束
  2. 水位状态跨区变化（健康→压力 / 压力→超限）
  3. 执行过 `memory_compact apply` 但仍处压力区
- **压力提醒极简**（评审修订）：只带水位百分比 + 冷候选**数量**（一行），
  不展开明细——明细在 `memory_compact report` 里看

### 2.3 compact apply 的语义（评审修订：结果评价 + 明确建议）

- `lowWater` 是**推荐健康目标线（结果评价线 + 建议依据）**，不是保证收敛目标——
  compact 不自动删除知识（与 P0.5「冷候选不自动清理」一致）
- `memory_compact apply` 执行后**报告整理后水位与明确下一步**：
  - 低于 lowWater → 「✅ 已回到健康区（水位 xx%）」
  - 仍在 lowWater~highWater → 「⚠️ 未到低水位（xx%）。建议：优先归档
    统计窗口内冷候选（见下）、合并重复主题、缩短 index 行描述、正文过长则拆分主题文件」
  - 仍超 highWater → 「❌ 仍处压力区——现有合并/归档不足以降水位。需人工：
    精简 index 文本或拆分 topic/file」+ 冷候选标题列表（≤5 条，report 级输出）
- 不新增自动删除逻辑；水位是**结果报告**

### 2.4 report 展示（评审修订：单状态，不并列）

```
- 索引：45 行 / 3.2KB（上限 200 行 / 25KB；高水位 160 行 / 20KB；低水位 120 行 / 15KB）
  当前：22%（健康）
```

压力区则：`当前：85%（压力区，建议 memory_compact 整理）`；超限则 `当前：104%（超限，部分条目未加载）`

### 2.5 配置（新增，均可选）

```yaml
- id: dsh-memory
  config:
    indexHighWaterRatio: 0.8   # 高水位比例（压力提醒触发线）；校验 0<low<high<1
    indexLowWaterRatio: 0.6    # 低水位比例（推荐健康目标线）
    pressureCooldownTurns: 5   # 压力提醒冷却（同目录 N 回合内不重复；状态变化重置）
```

## 4. 测试计划（tests/index-watermark.spec.ts）

1. **水位计算**：行/字节双维度、健康/压力/超限三态、边界值（恰等于 highWater）
2. **ratio 校验**：非法配置回退默认（反向/等值/越界）
3. **注入行为**：压力区注入 WARNING（水位 + 冷候选数量）；冷却内不重复；
   状态跨区重置提醒资格；健康区无压力提示；超限保留现有截断 WARNING
4. **compact 语义**：apply 后低于 lowWater → 健康报告；仍超 → 分级建议 + 冷候选列表
5. **report 展示**：单状态水位 + 高/低水位线
6. **配置**：ratio/冷却可调
7. **回归**：现有 133 测试全绿（默认 ratio 下健康区行为不变）

## 5. 决策点（评审已定）

| 决策点 | 结论 |
|---|---|
| 压力冷却独立配置 | ✅ 独立 `pressureCooldownTurns` + 状态变化重置（评审修订） |
| 水位维度任一越线 | ✅ 任一越线即触发（评审确认） |
| compact 未达低水位 | 不自动动，给**明确下一步建议**（评审修订）；冷候选列表在 report/outcome 输出 |
| `target: lowWater` 参数 | 不需要——apply 语义为「结果评价 + 建议」，不保证收敛 |
| 压力提醒带冷候选 | 只带**数量**（一行），明细在 report（评审修订） |

## 6. 明确不做

- 不做自动整理（任何水位都不在主任务回合自动跑）
- 不做"整理到恰好不超线"的微修式逻辑（低水位目标天然规避）
- 不新增删除逻辑（compact 维持现有合并/归档语义；冷候选不自动归档——P0.5 决策）
- 不做按条目的水位贡献分析（超出 P1 范围）
- 不新增删除逻辑（compact 维持现有合并/归档语义）
- 不做按条目的水位贡献分析（超出 P1 范围，telemetry 已够用）
