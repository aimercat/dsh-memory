# dsh-memory v1.1 P0.5：recall hit telemetry — 设计规格（定稿版）

> 状态：**定稿**。已吸收第三方补审修订（2026-08-19：通过，需修订）：
> ① stats 默认不进 Git（stats.local.json，commitTelemetry 开关）② meta.windowStartedAt
> ③ 报告文案「当前统计窗口内未命中」（冷候选信号，非清理候选）④ surfaced 通道
> 不并入命中 ⑤ key 弱稳定性为已接受取舍。

## 1. 目标

为记忆生命周期管理提供**数据基础**：
- compact 清理决策（统计窗口内 0 命中的冷候选）
- 跨工作区 recall 质量评估（across 通道命中率）
- 记忆价值排序（真命中热度 / surfaced 曝光度）
- 忽略/降级行为分布（reasonCode 统计）

## 2. 设计（定稿）

### 2.1 存储：`stats.local.json`（默认）/ `stats.json`（commitTelemetry: true）

```json
{
  "meta": { "version": 1, "windowStartedAt": "2026-08-19T00:00:00.000Z" },
  "entries": {
    "patterns.md|串行写队列": {
      "hits": 3,
      "lastHit": "2026-08-19T02:00:00.000Z",
      "channels": { "grep": 2, "surfaced": 0, "across": 1 }
    }
  },
  "ignored": { "duplicate": 1, "unconfirmed-3x": 2 }
}
```

- **默认 `stats.local.json`**（评审修订：telemetry 是运行期操作数据，非项目共识；
  默认不进 Git，避免提交/合并噪音与跨环境统计污染）。`commitTelemetry: true`
  时用 `stats.json`（可提交）。
- **meta.windowStartedAt**：统计窗口起点（首次记录时刻）；报告语义绑定窗口。
- key = `文件|标题`——**弱稳定标识（已接受取舍）**：改标题视为新条目、
  archive/restore 后可能断裂；升级 stable id 的路径保留在文档层面。
- 不污染知识文件。

### 2.2 打点通道

| 通道 | 触发点 | 语义 |
|---|---|---|
| `grep` | `searchMemory` 精确命中（行→条目映射） | **真命中**——模型确实看到了内容 |
| `across` | 跨工作区检索命中 | **真命中**（跨区） |
| `surfaced` | fuzzy 候选被返回 | **曝光/推荐**——被建议未必被读，**绝不并入 hits** |
| （ignored） | `memory_confirm ignore` / 自动降级 | 生命周期行为分布 |

### 2.3 消费：`memory_compact report` 集成（三段式）

```
📈 命中统计（stats.local.json，当前统计窗口自 2026-08-19 起）：
- 真命中 47 次（8 条）；曝光(surfaced) 12 次（4 条）
- 最热条目：串行写队列(9次)、L2 分层(6次)、外链策略(4次)
- ⚠️ 当前统计窗口内未命中的条目 4 条：xxx、yyy…（冷候选信号——
  需结合类别/年龄/近期编辑人工复核，不自动清理）
- 忽略/降级分布：duplicate:2、unconfirmed-3x:1
```

- 真命中（grep+across）与曝光（surfaced）**分开呈现，不合并**
- 0 命中 = **冷候选信号**（非清理候选）——结合类别/年龄/近期编辑人工判断
- 「从未命中」文案废弃（窗口语义：删 stats / 重置后所有条目瞬间 0 命中，
  旧文案会误导）

### 2.4 实现约束

- 全部写操作走 `serializedWrite`（并发安全）
- **best-effort**：打点失败不抛错、不影响调用方
- **await 而非 fire-and-forget**：确保测试可确定性清理
- 记录函数用 `fileName` 参数（recordIgnored 曾误用 STATS_FILE——已修复，
  否则 ignore 统计写进错误的文件）

## 3. 取舍与备选（评审点，已定）

| 决策点 | 结论 |
|---|---|
| stats 是否进 Git | **默认不进**（stats.local.json）；`commitTelemetry: true` 可开（评审修订） |
| 0 命中是否自动清理 | **不自动**——仅报告标注为冷候选信号（评审确认） |
| 重置工具 | **P1- 候选**（memory_stats reset，非 P0.5 阻塞） |
| surfaced 是否并入命中 | **绝不**——曝光 ≠ 命中，报告分开呈现（评审修订） |
| key 稳定性 | 弱稳定标识是**已接受取舍**（改标题=新条目） |

## 4. 测试（tests/telemetry.spec.ts，10 项）

累计/通道分离/lastHit、meta 窗口、损坏容错、grep/surfaced/across 打点、
非知识文件不计、ignore/degrade 打点、报告摘要（真命中/曝光/冷候选）、
compact report 集成。全套 133/133 绿。

## 5. 明确不做

- 不做按会话维度的命中归属；不做自动清理；不做跨工作区统计聚合。
